# Agent B: persistent graph and state

Brief: implement src/graph, src/store and deterministic graph tests against the lead-owned shared TypeScript contract. Single ordered worker, SQLite batch/cursor transaction, explicit nodes, durable action intents and conservative failure recovery. No model/network needed for graph tests.

Exports: `new Store({path,session,identity?,readOnly?})`; `new Graph({store,world,assess,precedents?})`; `graph.ingest(batch)`, `graph.drain()`, `graph.pollOnce()`, `graph.processEvent(event)`. Standalone `processEvent(event,dependencies)` shares implementation. Store exposes cursor, issues, inspect, reviewEvents, traces, intents and close. Inspection uses readOnly to avoid changing recovered state or requiring credentials. Live writer binding requires exact session and credential hash.

Optional `beforeEvent` delegates a persisted event to a durable extension handler; true checkpoints completion and a thrown failure leaves the event pending. `Store.reconcileCase(actionId,eventId)` is an explicit operator-confirmed local recovery operation: it requires a complete validated `case.created.payload.case` observation, exact creation field/property match, later cursor and a unique uncertain intent. It never retries the remote write. Partial, mismatched or ambiguous observed cases remain blocked. This payload shape is an integration assumption, not a guaranteed API field.

Graph steps: Ingest → Route → Assess → Validate → Act → Checkpoint. Route/Validate may finish directly without writes. Unknown payloads, conflicting links, missing actors, ambiguous replies and acknowledgements do not cause mutations. Explicit conversation links are decoder integration assumptions, not claimed API guarantees. Unlinked new tenant reports get fresh local IDs. Conservative reply heuristics hold ambiguous follow-ups; operator may need to improve this adapter using actual live envelopes.

SQLite stores original input events, issue evidence, outstanding question, remote IDs, action decisions/results and trace. Queued intents resume. In-flight intents become uncertain on restart and do not retry. Confirmed 429 is deferred with bounded attempts; new material evidence cancels stale deferred action for review. Auth/session-ended errors persist a mutation stop. API error details/hints are retained. Corrections reference an older event on the same issue; superseded citations are rejected by triage validation.

Checks actually run: `npm run build`; `node --test dist/tests/graph.test.js`: 16 passing at handoff. Coverage: one create/no announcement; same-case update/two independent reports; reply after SQLite restart; duplicates; cursor gaps/rollback; ambiguous/unknown/echo events; timeout after server creation/restart; interrupted intent recovery; session binding and writer lock; invalid model; 429/401/403; read-only inspection; cancellation of stale deferred writes; invalid corrections; queued unsent recovery; explicit reconciliation and mismatch rejection; extension hook retry after failure.

Inspectable example: timeout after fake server creation leaves one remote case, one uncertain action, issue status review and a Checkpoint/uncertain trace. The suite asserts no retry after restart. The public contract does not guarantee any event payload field correlating a created case to the dispatched request; title matching cannot prove uniqueness. Such outcomes remain unresolved for operator review rather than being automatically reconciled based on invented payload contracts. No real live-token run was made by this agent.
