# Scope, waiting and conversation reliability — implementation plan

1. Resolve cosmetic-record policy: recommended default is one low-priority remote case, with no automatic contractor assignment. This is a user-project prompt choice, not official Dwelly policy; user explicitly approved opening a low-priority case in this chat; no automatic contractor work.
2. Version the model contract with a separate required scope classification (maintenance, non-maintenance, external emergency, unknown). Bind actions to existing IDs. Reject contradictory scope/action pairs, while preserving old persisted executable decisions and explicit historical proposal replay.
3. Make waiting operational: require a named resume trigger; validate relevant known parties/outstanding questions; persist the wait with its origin. An explicitly configured operator review interval provides a deadline. Without that configuration, hold for review rather than silently waiting indefinitely. Due waits become visible operator-review items, never automatic remote writes. Material linked replies resume assessment and obsolete triggers are cleared.
4. Provide inspectable waiting/review queues and safe operator acknowledgement. Never clear uncertain-write holds through generic review commands. Keep restart and duplicate-delivery safeguards.
5. Add conversation fixtures for vague report/reply, worsening leak, corrected scope and contradictory evidence. Preserve contractor quote/approval/slot fixtures; add restart coverage where needed. Freeze variants and repeat counts before any model run. Keep labels out of model context; synthetic cases are not independently expert-labelled.
6. Compare a provisional baseline model and a cheaper candidate on the same fixed conversations and paraphrases. Report scope, urgency, action/extra-message errors, schema/provider failures, graph execution, timing and usage when actually returned. Do not select production defaults from a tiny dataset or rerun until passing.
7. Run strict build, offline tests, recording replay and clean-source verification. Document exact changes, executable commands, measured results and remaining live-integration/independent-evaluation limits.

Completion requires scope/action separation in the runtime, no newly created indefinite wait without a visible review path, repeatable multi-turn tests and reports, preservation of historical state, and a clear account of what remains unverified.

## Completed

All seven phases are implemented and verified. The user approved low-priority cosmetic case creation. The runtime separates scope/action, persists reviewable waits, and provides waiting inspection and acknowledgement. Frozen multi-turn paraphrases were measured twice per model against Claude Sonnet 5.5 and GPT-4.1 mini; both passed all 24 turns. All 109 offline tests, a fresh-source build/test and case-04 replay passed. See [results and remaining limits](scope-wait-results.md).
