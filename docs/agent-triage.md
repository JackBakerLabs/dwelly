# Triage agent handoff

Assigned scope: src/triage, deterministic triage tests and evaluation/replay fixtures. Shared interfaces are in src/types.ts; no shared interface edits made.

Reserved before deriving rubric: case-02, case-05, case-09, case-11. RUBRIC was derived from development cases only. selectGuidance always excludes reserved cases and also excludes a target whose ID matches issue.conversationId. Guidance includes only development classification/rationale, not archived correspondence or manager instructions. Held-out fixtures use the initial tenant report only; final classification and disposition are used solely by the scorer. The evaluator labels its report real-or-injected because callers may inject deterministic providers; the CLI is responsible for identifying a real provider run.

Exports: createModelAssessor({apiKey,model?,fetch?}), validateDecision(issue,input), buildCase04Replay(history), case04ScriptedAssessor, runEvaluation(history,assessor), selectGuidance, RESERVED_CASE_IDS. The provider uses native fetch to OpenAI Chat Completions with JSON-object response format and runtime strict validation. Official API reference checked during implementation: https://developers.openai.com/api/reference/resources/chat . The model defaults to gpt-4.1-mini and can be overridden. Provider HTTP failures surface review without retries; malformed model output gets one correction then review. Neither case mutations nor messages are exposed to this module.

Case-04 fixture wording, dates and names come directly from the pinned archive. Its event IDs, cursors, actor IDs and conversation_id are explicitly synthetic envelope metadata because history.json is not the live feed. The fixture stops before contractor attendance and includes the four preceding tenant messages, including the downstairs tenant. Scripted outcomes are medium open, wait, wait, high update. These prove graph plumbing, not model judgement. The explicit synthetic conversation link is necessary because actual live payload correlation has not yet been observed.

Checks actually run: npm run build succeeded; node --test dist/tests/triage.test.js passed 7/7. Tests cover invalid urgency/extra keys/unknown IDs, superseded evidence, held-out exclusion, chronological case-04 escalation, bounded model correction, credential-safe provider failure and evaluation context isolation.

No OPENAI_API_KEY is configured. Real-model evaluation was NOT run; no model accuracy is claimed. No live Dwelly token run was performed. Semantic model judgment remains unverified until the real evaluation executes. The runtime validator guarantees allowed shapes/IDs/known transitions, not that a plausible model explanation is factually correct.
